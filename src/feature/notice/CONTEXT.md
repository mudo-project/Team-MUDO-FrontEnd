# Notice(공지사항) Domain — CONTEXT
> 배치 경로: `src/feature/notice/CONTEXT.md`
> 목적: 이 문서를 읽은 사람 또는 AI 에이전트가 공지사항 도메인이 **무엇을 하는 도메인이고, 어떤 기능이 있으며, 어떤 조각으로 이루어져 있는지** 파악할 수 있게 한다.
> 구현 상태: **부분 구현**. `NoticeCreateForm`/`NoticeEditForm` 모두 모달 열기/닫기(내용이 길어져도 `max-h-[85vh] overflow-y-auto`로 모달 내부 스크롤), 제목·내용 필수값 검증(`react-hook-form` + `zod`, `src/lib/noticeCreateSchema.ts` 공유)까지 동작하는 클라이언트 컴포넌트로 구현되어 있다(실제 등록/수정 저장 로직은 없음). `NoticeDetail`의 `수정` 아이콘이 `NoticeEditForm`을 열고, 해당 공지의 제목·내용·상단고정·기존 첨부파일이 폼에 미리 채워진다. 파일 첨부·미리보기·삭제는 `NoticeFileUpload`로 분리되어 있고, 기존 첨부파일 표시까지는 지원하지만 zod 검증 대상은 아니다(값 채움만, 검증은 여전히 없음 — 의도적 결정). `NoticeList`는 `src/feature/notice/dummyNotices.ts`의 공유 더미 데이터를 렌더링하며 각 항목이 `/notice/[id]`로 이동하는 링크다. `NoticeDetail`은 그 id로 더미 데이터에서 공지를 찾아 상세 화면(고정 표시, 작성자, 본문, 첨부파일, 이전/다음 네비게이션)을 렌더링한다 — 이전/다음 이동은 실제로 동작하고, `NoticeDetailToolbar`(핀 아이콘)이 클릭마다 고정 배지를 켜고 끄지만 이는 컴포넌트 로컬 상태일 뿐 목록·서버에는 반영되지 않는다. 삭제 버튼은 시각적으로만 존재하고 클릭 동작·작성자 권한 판별은 없다. 검색, 공지 삭제, 고정 상태 영속화, 수정 결과 저장은 아직 미구현이다. `NoticeListItem`, `NoticeNavigation`(별도 컴포넌트로 분리 안 됨, `NoticeDetail` 내부에 직접 작성), `NoticeFileList`는 아직 사용되지 않는 뼈대 상태다.

## 1. 개요

전체 구성원에게 전달할 공지를 등록·조회하는 도메인.

작성자가 공지를 등록하면 모든 사용자가 목록에서 확인할 수 있고, 중요한 공지는 상단 고정해 강조할 수 있다.

### 핵심 제약

- 공지 작성 시 **제목·내용은 필수값**, **첨부파일·상단 고정은 선택값**이다.
- 상단 고정된 공지는 목록 최상단에 위치하며 중요 표시·강조 표시가 함께 나타난다.
- 상세조회 화면의 고정 등록/수정/삭제 버튼은 **작성자에게만** 노출된다.

### 진입점

Sidebar의 공지사항 메뉴(`src/components/layout/Sidebar.tsx`, `href: "/notice"`). 라우트는 `src/app/(user)/notice/page.tsx`.

## 2. 용어

| 용어 | 정의 |
|---|---|
| **공지 목록** | 등록된 공지를 나열하는 화면. 상단고정 여부·제목·파일첨부 여부·작성자·날짜를 표시 |
| **상단 고정 공지** | 고정 여부가 참인 공지. 목록 최상단에 위치하고 중요 표시·강조 표시가 붙음 |
| **공지 작성 모달** | 제목·내용·첨부파일·상단 고정 여부를 입력하는 모달. 수정 시에도 동일한 모달에 값이 채워진 상태로 재사용 |
| **공지 상세조회** | 목록에서 공지를 클릭했을 때 나타나는 단건 상세 화면 |
| **이전 공지 / 다음 공지** | 상세조회 하단에서 인접한 공지로 이동하는 네비게이션. 대상이 없으면 안내 문구 표시 |

## 3. 화면 구성

공지사항 도메인은 **목록 화면**과 **상세조회 화면** 두 개로 구성된다.

### 목록 화면

```
┌─ 공지 목록 화면 ────────────────────────────────┐
│ [Header]                                        │
│                        [검색]   [공지 작성]      │
├──────────────────────────────────────────────────┤
│ [목록]                                           │
│  고정 | 제목            | 첨부 | 작성자 | 날짜   │
│  📌   | (중요)제목A     | 📎   | 김지수  | 08.01 │
│       | 제목B           |      | 정다은  | 07.30 │
└──────────────────────────────────────────────────┘
```

- 검색 결과가 없으면 "검색 결과가 없습니다" 표시.
- 등록된 공지가 없으면 "등록된 공지가 없습니다" 표시.

### 상세조회 화면

```
┌─ 공지 상세조회 화면 ─────────────────────────────┐
│ [목록으로]                                       │
├───────────────────────────────────────────────────┤
│ [Header]                                          │
│  (고정 표시) [고정 등록/수정/삭제]* 작성자 작성일 │
│  조회수  읽음수                                   │
│  * 작성자에게만 노출                              │
├───────────────────────────────────────────────────┤
│ [본문]                                            │
│  공지 내용                                        │
│  첨부파일 (개수)                                  │
│   - 파일명   크기   [다운로드]                    │
├───────────────────────────────────────────────────┤
│ [Footer]                                          │
│  ◀ 이전 공지: 제목 / 없으면 "이전 공지가 없습니다"│
│  ▶ 다음 공지: 제목  / 없으면 "다음 공지가 없습니다"│
└───────────────────────────────────────────────────┘
```

## 5. 데이터

공지 1건이 가지는 정보. 현재는 `src/feature/notice/dummyNotices.ts`의 `DummyNotice` 타입으로 정의된 더미 데이터다 — 실제 API 연동 시 이 타입/파일은 대체·삭제될 예정이다.

| 항목 | 필드명(더미) | 설명 |
|---|---|---|
| 아이디 | `id` | 상세조회 라우팅(`/notice/[id]`), 이전/다음 탐색의 기준값 |
| 제목 | `title` | 목록·상세조회 상단에 표시. 검색 기준값. 필수 |
| 내용 | `content` | 공지 본문. 필수. 상세조회에서만 표시 |
| 첨부파일 | `attachment`(목록용 boolean), `file`(상세조회용 `{ name, size, extension }`) | 선택. 목록에는 이모지만, 상세조회에는 파일명·크기·다운로드 버튼 표시 |
| 상단 고정 여부 | `important` | 참일 경우 목록·상세조회에 고정 배지 표시. 선택. (목록 "최상단 정렬"은 아직 미구현) |
| 작성자 | `author`, `authorRole` | 목록·상세조회에 표시. 작성자만 상세조회의 고정 등록/수정/삭제 버튼을 볼 수 있어야 함(미구현, 현재는 항상 노출) |
| 작성일 | `date`(목록용 짧은 표기), `datetime`(상세조회용 전체 표기) | 목록·상세조회에 표시 |
| 조회수 | `viewCount` | 상세조회에 표시 |
| 읽음수 | `readCount`, `totalMemberCount` | 상세조회에 `읽음 N/M` 형태로 표시 |

## 6. 컴포넌트 구성

기능 단위로 분해했을 때 필요한 컴포넌트 목록과 각자의 책임. `src/feature/notice/components/`에 아래 컴포넌트 파일이 생성되어 있다.

목록 화면은 `src/app/(user)/notice/page.tsx`, 상세조회 화면은 `src/app/(user)/notice/[id]/page.tsx`(동적 라우트, 구현 완료 — `params`를 `await`해서 `id`를 `NoticeDetail`에 전달)로 분리된다.

| 컴포넌트 | 책임 |
|---|---|
| **(page.tsx)** | 목록 화면 셸. `src/app/(user)/notice/page.tsx`. 검색창·작성 버튼·목록을 배치. Header를 별도 컴포넌트로 분리하지 않고 이 안에 직접 작성 |
| **NoticeSearch** | 제목 검색 입력. 검색 결과 없음 상태 처리 (아직 입력 UI만 있고 검색 로직 없음) |
| **NoticeList** | 공지 목록. `dummyNotices`를 순회하며 각 항목을 `next/link`로 감싸 `/notice/[id]`로 이동시킨다(서버 컴포넌트 유지, `hover:cursor-pointer`). 항목이 없을 때 안내 문구는 아직 미구현. `NoticeListItem`을 쓰지 않고 항목 마크업을 직접 그림(아래 참고) |
| **NoticeListItem** | 목록 항목 1건을 위해 계획된 컴포넌트지만 아직 사용되지 않는 뼈대 — `NoticeList`가 항목 마크업을 직접 들고 있다. 항목 마크업이 더 복잡해지면 분리 |
| **NoticeCreateForm** | 클라이언트 컴포넌트. `공지 작성` 트리거 버튼과 작성 모달을 함께 소유한다(`useModal` 훅으로 열림/닫힘 상태 관리, `max-h-[85vh] overflow-y-auto scrollbar-hide`로 모달 내부 스크롤·스크롤바 숨김). `page.tsx`가 서버 컴포넌트로 유지되도록 트리거 버튼도 이 컴포넌트 안에 둠. 제목·내용은 `react-hook-form`의 `useForm` + `src/lib/noticeCreateSchema.ts`(`zodResolver`)로 검증하고, 상단 고정은 검증 규칙 없이 폼 값(타입)으로만 등록. 첨부파일 입력은 `NoticeFileUpload`를 그대로 배치(아직 폼 검증에는 편입 안 됨). 실제 등록 저장 로직은 아직 없음 |
| **NoticeFileUpload** | 클라이언트 컴포넌트. `NoticeCreateForm`/`NoticeEditForm`에서 공유하는 첨부파일 전용 컴포넌트. 새로 추가한 파일(추가/미리보기 `URL.createObjectURL`/삭제)은 자체 `useState`로 관리하고, 언마운트 시(모달이 닫혀 조건부 렌더링에서 빠질 때) 미리보기 URL을 `useEffect` cleanup으로 정리. `initialFiles?: { name, size }[]` prop을 받아 이미 저장된 파일(이름·크기만 있고 실제 `File` 객체는 없음)을 목록에 미리 채워 보여준다 — 기존 파일은 "미리보기" 없이 "삭제"만 가능(실제 blob이 없어 미리보기 불가). 값 채움만 담당하고 zod 검증 대상은 아님(의도적 결정) |
| **NoticeEditForm** | 클라이언트 컴포넌트. `notice: DummyNotice`를 props로 받아 `공지 수정`(연필 아이콘) 트리거와 수정 모달을 함께 소유한다. `NoticeCreateForm`과 동일하게 `useModal` + `react-hook-form`(`noticeCreateSchema`, `zodResolver`) 구조, 모달 스크롤·스크롤바 숨김(`max-h-[85vh] overflow-y-auto scrollbar-hide`)도 동일하지만 `defaultValues`를 `notice`의 제목·내용·`important`로 채우고, `NoticeFileUpload`에 `initialFiles`로 기존 첨부파일을 넘긴다. 제출 버튼 라벨은 `수정`. 실제 수정 저장 로직은 아직 없음 |
| **NoticeDetailToolbar** | 클라이언트 컴포넌트. `notice: DummyNotice`를 props로 받아 고정 배지 + 고정/수정/삭제 아이콘 버튼 행 전체를 소유한다. `pinned` 로컬 `useState`(초기값 `notice.important`)로 배지 표시와 핀 아이콘 `aria-label`("상단 고정"/"상단 고정 해제")을 토글한다. 배지(왼쪽)와 핀 버튼(오른쪽, `ml-auto` 그룹)이 같은 상태를 공유해야 해서 `NoticeDetail`에서 분리 — 서로 다른 두 위치가 하나의 상태를 참조하려면 공통 부모가 클라이언트 컴포넌트여야 함. `NoticeEditForm`을 이 버튼 그룹 안에 그대로 둠(위치상 여기 속함). 고정 상태는 로컬 상태일 뿐 목록·서버에는 반영되지 않음 |
| **NoticeDetail** | 상세조회 화면 본문. `/notice/[id]/page.tsx`가 `id`(string)를 props로 넘겨준다. `dummyNotices`에서 `id`로 공지를 찾아(없으면 "공지를 찾을 수 없습니다") 목록으로 링크, `NoticeDetailToolbar`(고정 배지+고정/수정/삭제), 작성자·작성일·조회수·읽음수, 본문, 첨부파일 1건, 이전/다음 네비게이션까지 전부 이 컴포넌트 안에서 직접 그린다. 서버 컴포넌트(자체 상태·이벤트 없음, `NoticeDetailToolbar`만 클라이언트) |
| **NoticeFileList** | 상세조회에서 첨부파일을 여러 건 나열하기 위해 계획된 컴포넌트지만 아직 사용되지 않는 뼈대 — `NoticeDetail`이 파일 1건 표시를 직접 그린다 |
| **NoticeNavigation** | 상세조회 하단 이전/다음 이동을 위해 계획된 컴포넌트지만 아직 사용되지 않는 뼈대 — `NoticeDetail`이 이전/다음 링크를 직접 그린다 |

> `memo` 도메인이 작성 폼과 수정 폼을 `MemoCreateForm` / `MemoEditForm`으로 분리한 것과 동일하게, 공지도 작성 폼과 수정 폼을 분리하는 구조로 확정.
> `memo` 도메인의 `MemoContainer`가 Header를 별도 컴포넌트로 분리하지 않은 것과 동일하게, 목록 화면(`page.tsx`)과 `NoticeDetail`도 각자의 Header 영역을 내부에 직접 작성한다.
> `NoticeFileUpload`(작성/수정 폼에서 첨부·미리보기·삭제)와 `NoticeFileList`(상세조회에서 읽기 전용 목록·다운로드, 아직 미사용)는 이름이 비슷하지만 역할이 다른 별개 컴포넌트다. 혼동 방지를 위해 의도적으로 이름을 다르게 두었다.
> `NoticeListItem`, `NoticeFileList`, `NoticeNavigation`은 파일은 만들어져 있지만 실제로는 쓰이지 않는다 — `NoticeList`/`NoticeDetail`이 해당 마크업을 직접 들고 있다. 각 화면이 복잡해지면 그때 분리한다(현재는 분리할 만큼의 중복·복잡도가 없음).

### 관계

```
notice/page.tsx                    (목록 화면, /notice)
├── NoticeSearch
├── NoticeList                     (각 항목이 Link로 /notice/[id] 이동)
└── NoticeCreateForm                (작성 버튼 클릭 시)
    └── NoticeFileUpload

notice/[id]/page.tsx               (상세조회 화면, /notice/[id])
└── NoticeDetail                   (목록으로 링크, 이전/다음 링크 포함)
    └── NoticeDetailToolbar        (고정 배지 + 고정/수정/삭제 버튼, 고정 로컬 토글)
        └── NoticeEditForm         (수정 아이콘 클릭 시, notice로 값 미리 채움)
            └── NoticeFileUpload   (initialFiles로 기존 첨부파일 미리 채움)
```

### 컴포넌트 외 필요한 조각

| 조각 | 역할 | 상태 |
|---|---|---|
| 공지 데이터 | 목록·상세조회·CRUD | 미구현 — `src/feature/notice/dummyNotices.ts`의 공유 더미 데이터로 대체 중 |
| 검색 상태 | 현재 검색어, 필터링된 목록 | 미구현 |
| 작성자 권한 판별 | 고정 등록/수정/삭제 버튼 노출 여부 결정 | 미구현 |
